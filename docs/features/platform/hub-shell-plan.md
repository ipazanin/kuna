The first hub wave re-checked against the code at 77eec40, after the JSON storage, the sync engine, onboarding, mail and Salaries landed: what still holds from the proposal, the target folders, the app seam, routes, settings and one document per app, the boundary rules, five build stages with their proof, and three decisions for the owner.

Background: [the proposal](../../architecture/hub.md) with the owner's decisions of 2026-10-22, and the Finance hub section of the plan.

## In short

- **The aim is unchanged.** The company app becomes the first app inside a thin shell. Figures stay the same, nothing changes on screen, and the addresses gain `/company`.
- **JSON storage did half the storage work.** The document already names its app (`"app": "company"`, `documentFormat.ts:10-16`), and the Drive home already takes the app id (`driveDocument.ts:74`, `:87`, `:101`). With JSON, "one storage per app" means one document per app, so H1 moves the document machinery into the kernel and changes no stored byte.
- **The store stays the company's in H1.** `createWorkbookStore` is typed to the company `Workbook` (`createWorkbookStore.ts:5-6`, `:175`, `:190`). It becomes generic in H2, when a second app needs it.
- **Five stages, one commit, one deploy.** Kernel prep (medium), the move (large, mechanical), the shell and app seam (medium), the boundary rules (small), docs (small). About 500 files moved.
- **Three decisions for you:** when the app moves to its new name and address, whether addresses gain `/company` now, and whether the figure check gets committed.

## Decisions for the owner

**The owner, 2026-10-28:** all three as recommended. Keep `/ledgerboard/` in H1 and move in its own wave before H2, add `/company` now, commit the figure check.

### 1. When does the app move to its new name and address?

**Affects** the installed app on your phone, the address you open, and Google sign-in. Today the home-screen icon opens `ipazanin.github.io/ledgerboard/`. After a move, that icon keeps opening the old address. You install again from the new one, and Google needs the new address as an authorised redirect.

- **Keep `/ledgerboard/` in H1, move in its own small wave once you pick the name.** H1 changes only the part after `#`. Cost: a later wave touches the base (`vite.config.ts:10`), the redirect the app sends (origin plus base, `googleAuth.ts:114`), the worker scope (`appUpdate.ts:53`), the manifest (`manifest.webmanifest:2-4`), the checks' base (`runSelection.mjs:28` and the CI `curl`), a new redirect URI in Google Cloud (your yes), and a reinstall.
- **Move with H1.** One wave, one reinstall. Cost: the name has to be chosen first, and H1 then mixes a Cloud change with a 500-file move, so a sign-in failure after the deploy is harder to place.

Unverified either way: the browser's data should survive, since every path on `ipazanin.github.io` is one origin. Access to `ledgerboard-company.json` under `drive.file` should follow the OAuth client, not the address, if the client stays the same. Whether GitHub Pages redirects the old path after a repo rename is unconfirmed. Recommendation: keep `/ledgerboard/` in H1, and move just before H2, when a second app makes the hub visible.

### 2. Do addresses gain `/company` now?

**Affects** every address, bookmark and link the app writes. Today `#/owner?tab=owed` opens Owner, Owed. After H1 it is `#/company/owner?tab=owed`, and the old link opens Overview.

- **Add the prefix now.** One rewrite while nothing else is in flight, and the router checks from the start that an app's routes stay under its id. Cost: old bookmarks land on Overview once, plus the literal rewrite in stage 3.
- **Add it with the second app.** H1 keeps every address. Cost: H2 does the same rewrite while it also adds a second storage, and H1's router has no prefix to check.

Recommendation: now.

### 3. Does the figure check get committed?

**Affects** how every wave proves its figures identical, this one first. Each wave since 12b wrote its own scratch script. After H1's move the old ones no longer resolve their imports.

- **Commit `scripts/figure-digest.mjs`.** It reads the fake books or a file given by path (xlsx or the JSON), runs the read path and the engines behind each screen, and prints a count and a digest per figure group, never a figure, so it is safe on real data. Two runs compare with `diff`. Added in stage 0 at today's paths, the codemod then rewrites it like any script. Cost: about 150 lines to keep current when a screen gains a figure.
- **Keep scratch scripts.** Cost: H1's script needs a path table for each layout, and every later wave writes one again.

Recommendation: commit it.
