# H2 lane 1: storage, store, sync and device state

Every single-app assumption in Kuna's storage, workbook store, sync engine and device keys at 286a002, what is already per app, and the smallest change that lets a second storage and an empty personal app in.

Read-only research on the Kuna repo at HEAD 286a002. Paths are relative to the repo. One scratch script checked the empty document claims. It was a scratch file, `empty.mjs`, run with `node --import ./scripts/support/typescriptResolve.mjs`. No web page is cited.

## Headline facts

- The document layer is already per app. File name, appProperty, backup names, the browser database and the cache database all take an app id or a document id. Nothing in `src/shared/storage` names the company.
- The single-app assumptions sit one level up, in code that is generic in shape but lives in `src/apps/company`: the workbook store, the store's ports, the Google Drive access, the fake Drive, the sync engine and auto-sync. The import rule "each app keeps to its own folder and the shared kernel" (`tests/importBoundaries.spec.ts:140-142`) means the personal app cannot reuse any of it where it is. Most of H2's storage work is moving those files into `src/shared` with the app id as a parameter.
- Only one device key is truly single-app: the workbook choice `kuna.workbook-file` (`src/shared/storage/infrastructure/workbookChoice.ts:4`).
- An empty personal document encodes, decodes and takes a first write with today's code. No codec or format change is needed.
- Money format is one page-wide value that the company store sets on every `show()` (`src/apps/company/workbook/application/createWorkbookStore.ts:190`, `src/shared/money/moneyFormat.ts:31-38`). Two stores reusing that `show()` would race, and the last one to open would win.
- Two Google behaviours turn wrong with two storages: keeping one storage in the browser forgets the page's Google sign-in for every storage (`createWorkbookStore.ts:415`), and a redirect that resumes `find` or `pick` carries no app id (`src/shared/google/googleRedirect.ts:20`).

## 2. Smallest generalisation

The plainest design is one store per storage, made by the same shared factory, with the app id passed in. No registry of stores and no store-of-stores is needed. Each app owns its store and hands the shell what the shell shows.

1. **Choice key per app.** `loadWorkbookChoice(app)` and `saveWorkbookChoice(app, choice)` in `workbookChoice.ts`, key `kuna.workbook-file.<app>`. Callers: `workbookStore.ts:51-52`, `app.ts:65`, `seedFakeWorkbook.ts:35`, `:71`. See the open question on the company key below.
2. **Move the store factory to shared.** `createWorkbookStore.ts` to `src/shared/storage/application/`, generic over the read model: `WorkbookStore<Copy, Contents, Books>` with `read(copy): Books`. Keep the field names `workbook` and `records` so the 70 files that call `useWorkbook()` do not change. Take `setMoneyFormat` out of `show()` (`:190`). Take `forgetGoogleSignIn()` out of `replaceLocalWorkbook` (`:415`) and let the caller forget the sign-in only when no other storage of the device is on Drive. 28 files import the module.
3. **Move the store ports to shared.** `documentStorePorts.ts` to `src/shared/storage/infrastructure/`, as `documentStorePorts(app, { schema, codecOf, read }, driveAccess, now)`. `COMPANY_APP`, `installedSchema` and `readDocument` stay in a small company file. Add the `document.app` check to `readFile`. 21 files import the module.
4. **Move the Google Drive access to shared.** `GOOGLE_DRIVE_ACCESS` (`workbookStore.ts:18-36`) with the Picker title as an argument. One instance serves both apps, since the token is page-wide.
5. **Move the fake Drive to shared.** `fakeDrive.ts` and `fakeDriveSession.ts` to `src/shared/storage/infrastructure/fake/`. `fakeBooksFile` picks the file tagged `kuna=<app>`. A personal fake browser id must differ from `FAKE_WORKBOOK_ID`, or both apps would open the same `kuna-document-*` database. `scripts/assert-no-fake-bytes.mjs` already guards the marker.
6. **Sync over every storage.** Make the sync engine Workbook-free and move it to shared: `SyncStep.scopes()` and `on()` close over their own app's store instead of taking a `Workbook`. Group steps by app, each group a books step plus its own steps, and skip only the group whose books failed. The shell runs the groups one after another under one tap. `SyncScope` (`src/apps/company/sync/domain/syncRun.ts:4`) duplicates `GoogleScope` (`src/shared/google/googleScopes.ts:4`), so the move drops one of them. The personal group in H2 is a books step only.
7. **Needed scopes as a union.** The shell sums each app's needs and calls `needScopes` once. Today only `useSync.ts:47` calls it, so nothing breaks until a second caller appears.
8. **Auto-sync and silent sign-in over every storage.** `startAutoSync` takes the shell's sync and the oldest `syncedAt` among Drive storages. `main.ts:20` asks whether any installed app wants the silent trip. The switch file moves to shared or shell.
9. **Redirect carries the app.** Add the app id to `PendingRedirect` (`googleRedirect.ts:27-33`) for `find` and `pick`, and let `useGoogleReturn` act only on its own app. The pending `route` cannot tell the app apart, since Settings at `#/settings` serves both.

Not needed: any change to `browserDocument.ts`, `workbookCache.ts`, `driveDocument.ts`, `documentFormat.ts`, `documentRecordStorage.ts` or `recordWrites.ts`.

## 3. Record kinds, schema and an empty document

- A kind is a plain value (`src/shared/storage/domain/recordKind.ts:9-17`) and its id prefix is the kind name (`src/shared/storage/domain/recordId.ts:10-12`). There is no global registry. A codec lookup is a function passed to the storage (`src/shared/storage/domain/recordCodec.ts:24`, `documentRecordStorage.ts:173`). The company's lookup is its own (`src/apps/company/workbook/application/recordCodecs.ts:15-40`). A personal app passes its own `codecOf`, with zero kinds or one.
- Kind names only need to be unique inside one document, so a personal `setting` kind would not clash with the company's (`src/apps/company/workbook/domain/coreKinds.ts:16`).
- Schema is a map of contributor to version (`documentFormat.ts:11`). The company writes `{ core: 1, <pack>: n }` (`documentStorePorts.ts:29-32`). Personal would write `{ personal: 1 }`.
- Checked with the scratch script: `newDocument('personal', { personal: 1 }, {}, …)` encodes as `"records": {}` (`documentFormat.ts:41`), decodes back unchanged, is not newer for `{ personal: 1 }`, reads an absent kind as no records (`documentRecordStorage.ts:36`), and takes a first `add` that creates the kind's array (`documentRecordStorage.ts:114`). A schema of `{}` also round-trips.
- The same script shows the company's schema reads a personal file as saved by a newer app, since `personal` is a contributor it lacks (`documentFormat.ts:22-24`). That is the right answer for a write, but the `document.app` check from step 3 should refuse it earlier with a clearer message.
- Write rules are per kind and name no app (`src/shared/storage/domain/writeRules.ts:37-49`).

## 4. Google scopes

- A second file under `drive.file` needs no new scope and no new consent. The same client creates it, and `findByAppProperty` finds it on other devices the same way it finds the company file today (`driveDocument.ts:87-93`).
- The app already creates folders in the books folder from any device: `backupsFolder()` creates `backups` beside the file (`driveDocument.ts:124-127`). So creating the personal file beside the company file, or in a newly picked folder (`documentStorePorts.ts:143-146`), uses existing paths. Creating it in the company file's folder without a Picker is unverified on Google's side.
- Every token ask carries `drive.file` plus the device's needed list (`googleAuth.ts:193-194`). An empty personal app needs nothing else.
- Needed scopes are one device list (`googleSession.ts:33-40`). It survives sign-out by design (`googleSession.ts:56-61`). With two apps it must be the union, as step 7 says.
- `requestAccess` has no guard against a second ask while one is open (`googleAuth.ts:193-234`). A sync that read two storages in parallel without a token would open two popups, or on a phone overwrite the pending redirect. Running the storages one after another under one ask avoids it.

## 5. Currency and number locale

Today both live in the company document's `setting` records, keys `currency` and `number_locale` (`src/apps/company/settings/domain/settings.ts:39-41`, `:383-402`), defaulting to EUR and en-GB (`settings.ts:137-138`, `src/shared/money/moneyFormat.ts:18`). The store copies them into the page-wide format on each `show()` (`createWorkbookStore.ts:190`). 54 files format money through that global.

The company also uses `numberLocale` outside the global: the invoice PDF (`src/apps/company/invoicing/infrastructure/invoicePdf.ts:110`, from `useInvoiceRun.ts:189`) and three hr-doo panels. So the locale is part of what the company sends to clients, not only a screen preference.

What moves once a second storage exists:

- **Each document keeps its own two settings, and the app on screen sets the format.** The store stops calling `setMoneyFormat`. Each `AppContribution` says its format, and the shell applies it when the route enters the app. Personal in H2 has no settings kind and shows EUR and en-GB from `DEFAULT_MONEY_FORMAT`. This is the smallest change and keeps company and personal data apart. Settings at `#/settings` belongs to no app, so it needs a rule. The plainest rule is the home app's format there.
- **Locale moves to This device, currency stays in each document.** Fewer settings for a person to repeat, but the invoice PDF would then change with the device that ran the invoice, which is wrong for a document sent to a client.

I recommend the first. One later-wave cost is worth knowing now: when personal screens show company facts live, one screen will hold two currencies, and the global format cannot do that. That wave will need `formatMoney` to take an explicit format.

## 6. Export

- Today export writes the company books as xlsx through the company tab mapping (`src/apps/company/workbook/presentation/workbookFiles.ts:99-108`), named `kuna-<company or file name>-<yyyy-mm-dd>.xlsx` (`:111-118`), and downloads it (`src/shared/files/downloadFile.ts:5-14`). Three buttons use it: the browser status bar, Settings and the switch dialog (`src/apps/company/workbook-files/presentation/useExport.ts:15-34`).
- Export history is per copy: `lastExportedAt` and `unexportedSince` in `CopyMeta` (`workbookPorts.ts:20-23`), written by `recordExport` (`createWorkbookStore.ts:420-427`) and kept across reads (`:246-249`). The week reminder is a plain function (`src/apps/company/workbook-files/domain/exportReminder.ts:7-9`). So "one export per storage" already holds at the store level.
- For personal the plainest export is the document itself: `encodeDocument(snapshot.document)` downloaded as `kuna-personal-<yyyy-mm-dd>.json`. Import already reads a Kuna JSON file back (`workbookFiles.ts:65-77`), and an empty document round-trips (section 3). The xlsx path is company-only by nature.
- `exportReminderDue` and the download wrapper can move to shared, so each app's This device card offers its own export.

## Risks

- **Choice key rename and browser-kept books.** Renaming `kuna.workbook-file` leaves Drive books one "Find on Drive" tap away, since the file is found by its mark. Books kept only in the browser would lose their pointer, and their `kuna-document-local-*` database would be orphaned. 286a002 already dropped the old `ledgerboard.*` keys the same way.
- **Money format race** if the shared store keeps `setMoneyFormat` in `show()`. Both apps open their store at start (`autoSync.ts:68`), and whichever finishes last sets the format for every screen.
- **Sign-in lost** when either storage moves into the browser (`createWorkbookStore.ts:415`).
- **Two Pickers after a phone redirect** without the app id on the pending redirect.
- **Concurrent saves of two documents are safe.** They are different files with separate homes, revisions and backup state (`documentStorePorts.ts:84-90`, `driveDocument.ts:102`). The only shared resource is the page token.
- **Fake build:** the fake Picker's first-file rule, a shared `FAKE_WORKBOOK_ID`, and `?fake=` read only by the company install (`src/apps/company/app.ts:37-43`). `check:figures` (`scripts/figure-digest.mjs:55`) and `check:round-trip` (`scripts/round-trip-workbook.mjs:16`) import `COMPANY_APP` from `documentStorePorts.ts`. They break on the move, not on the behaviour. The visual check's screen list is all `#/company` (`scripts/visual-check.mjs:186-204`) and needs a personal entry once the app has a screen.
- **Tests that pin the company ports:** `tests/workbookStore.spec.ts:13`, `tests/recordStorageContract.spec.ts:32` and `tests/workbookCache.spec.ts:27` import or name `company`. They move with step 3 but should keep testing the company wiring.

## Open questions for the owner

- **Company choice key.** Rename it to `kuna.workbook-file.company` and accept one Find tap per device, or read the old key once. Renaming is safe only if no device keeps the company books in the browser alone.
- **Where currency and locale live.** I recommend each document keeps its own, and the app on screen sets the format.
