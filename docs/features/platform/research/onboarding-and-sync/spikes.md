## What this means

- **One token, one trip (stage 2):** possible. A silent trip returns every granted scope in one token in under half a second in Chrome. A scope never granted makes the whole silent trip fail, so stage 2 must ask only for scopes the user already granted, and send a newly turned-on scope through one consent trip.
- **Mail (stages 5 and 6):** Gmail reads work, the filed files carry `sha256Checksum` for the byte check (fall back to `md5Checksum` when a file lacks it), and the app can create files in the scripts' folders. Restricted scopes are not declared on Data access and still work for the owner's own account in production.
- **Firefox refuses the silent trip that Chrome allows.** A rerun of 2B at 10:18 with the owner's account typed as the hint still gave `interaction_required`, so the missing hint is not the cause. Left as candidates: no Google session in Firefox, or Firefox's protections (cookies or bounce tracking) on accounts.google.com. Stage 2 therefore keeps the popup on desktop Firefox (decision 2's fallback) and uses the silent trip only where a spike showed it working. Today's silent ask on every open fails the same way in Firefox, which is why auto-sync on open rarely ran on the Mac.
- **Folder path (decision 6):** confirmed. `drive.file` alone cannot read a picked folder's parent, so the folder step shows the name with Open in Drive unless Drive read is granted.
- **Still open:** the cause of Firefox's `interaction_required`, and the Android spikes 6 and 7.
